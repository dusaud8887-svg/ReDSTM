## 1. 한 번의 독서 세션 = history entry 하나

개편 M0의 저장소 계정 경계: `GET /api/v1/me`는 서버가 검증한 Access 사용자 email의 SHA-256 앞 16자리 `{ownerHash}`만 반환하며 `private, no-store`다. Basic 로컬 인증과 서비스 토큰에는 제공하지 않는다. 버전 디렉터리 `/fonts/<name>@<version>/`·`/vendor/<name>@<version>/`의 성공한 자산 응답은 public 1년 immutable이며, 기존 경로와 인증 요구는 유지한다.

| 행동 | history |
|---|---|
| 목록·홈·목차에서 본문 열기 | push 1회 (`redstmReader`, `redstmParent=<열었던 목록 경로>`) |
| 이전/다음, 본문 끝 다음 편, 옆 목록에서 다른 행 선택(데스크톱) | replace |
| 시스템 Back / 상단 `‹ 목록` / 하단 `목록` / 본문 끝 `목록으로` | 모두 같은 동작: parent가 있으면 `history.back()` |
| 본문 → `작품 목차` | 그 목차에서 들어왔으면 back, 아니면 목차가 본문 entry를 replace |
| 홈 `이어서 읽기`(작품 소속) | 목차 entry를 먼저 쌓고 본문 push → Back 순서: 본문 → 목차 → 홈 |
| 직접 링크(`/read/…`, `/collections/…`, `/text?…&chapter=`) | 첫 진입에 한 번만 부모 목록을 합성(게시판 목록 / 작품 목록 / 회차 목록). 새로고침으로 다시 쌓이지 않음 |

텍스트 장서(소설·아카라이브)도 같은 규칙을 쓴다. 목록 단계(작품→회차, 게시판→분류→글)는 단계마다 push하고, `← 작품 목록`은 부모가 바로 아래 entry면 back이다.

## 2. 회차 순서는 목록 정렬과 무관하다

- 타입문넷 작품: 작품 `position` 순. 보존되지 않은 편은 건너뛰되 본문 끝 카드에 `N편은 보존되지 않아 M편으로 이어집니다`를 표시.
- 텍스트 소설: 회차 파서의 오래된순(정규 순서). 목록을 최신순·이름순으로 보여도 `다음 화`는 항상 다음 회차. 저장함에서 연 회차도 작품 목차를 불러와 순서를 가진다.
- 아카라이브·작품에 속하지 않은 글: 본문을 연 순간의 목록 순서를 고정해 `이전 글/다음 글`로 이동.
- 현재 항목을 순서에서 찾지 못하면 이동하지 않는다(다른 글로 대체하지 않음). 순수 함수 `public/sequence.js`.

## 3. 목록 위치 복원

- 목록 행마다 안정 키(`data-key`: 글 identity, `collection:<id>`, 편 번호, `chapter:<id>`, `work:<id>`)를 둔다.
- 떠날 때 **맨 위에 보이던 행과 그 오프셋**을 저장하고, 돌아오면 그 행을 같은 오프셋에 맞춘다(`public/list-anchor.js`). 읽음 배지 등으로 위쪽 행 높이가 바뀌어도 화면이 밀리지 않는다.
- 결과 목록은 기존 `lastCatalogState`(불러온 개수·포커스)에 anchor를 더했고, 작품 목차와 텍스트 목록은 경로별 snapshot(sessionStorage, 최근 40개)을 쓴다.
- 목차에서 마지막으로 읽은 편은 강조(`current`), 텍스트 회차 목록 맨 위에는 `이어 읽기 · N화` 행이 생긴다.
- 홈 `이어서 읽기`는 타입문넷과 텍스트 중 더 최근에 읽은 것을 보여 준다. 텍스트는 Back이 본문 → 회차 목록 → 홈 순서이고, 다 읽은 소설 회차는 곧바로 다음 화를 연다(Back: 다음 화 → 회차 목록 → 홈). 텍스트 기록에 `title/work/route/listRoute`를 함께 저장한다(이전 기록은 다음에 열 때부터 대상).
- 긴 작품 목차에는 `회차로 이동`(번호 입력 → 가장 가까운 편 행으로 이동, 열지는 않음).

## 4. 공통 Reader

- 타입문넷과 텍스트가 **같은 DOM**을 쓴다(`#reader`, `data-source`). 텍스트 전용 뷰어는 제거했다.
- 모바일 하단: `목록 | 이전 | 다음 | Aa 설정 | 더보기`. 이전·다음이 붙어 있고 다음이 가장 넓고 강조된다. 저장은 상단 context bar 오른쪽과 더보기에 있다.
- 모바일 상단: 앱 바 대신 `‹ 목록 · 작품명 N/M · 저장` context bar. 도구 접기 규칙은 §4.3.
- 본문 끝 카드(댓글보다 먼저): 다음 편/화 제목이 적힌 큰 버튼 → `목록으로`·`작품 목차` → 작게 이전 편. 마지막이면 `작품 목차로 돌아가기`/`회차 목록으로`. 본문 끝 카드로 넘기면 현재 편을 완독 처리하고, 하단 `다음`은 완독 처리하지 않는다.
- 더보기 시트(모든 폭, 데스크톱은 도구줄 `⋯`): 작품 목차 · 저장 · 메모·태그 · 원문 열기 · AA/소설 보기 · 집중 모드 · 링크 복사 · 화면 켜 두기. 가능한 항목만 보인다(§4.4).
- 진행률은 본문 끝 기준이다(긴 댓글이 완독을 막지 않음).
- 상단 context bar에 읽은 %를 표시하고, 더보기의 `읽은 위치` 슬라이더로 긴 본문 안을 이동한다(100%는 다음 화 카드). 가장자리 드래그 스크롤바는 Android 제스처 Back과 겹쳐 쓰지 않았다(구 DSOTM 미니맵의 대체).
- 본문 맨 위 근처(80px)에서는 도구가 항상 보인다.
- 현재 편이 안정되면 다음 편 객체를 한 번 미리 받는다(`requestIdleCallback`, 데이터 절약 모드 제외). 아카이브·텍스트 객체는 immutable 캐시라 다음 이동이 캐시에서 열린다.
- 텍스트 소설 본문 앞의 수집 wrapper(`# 제목` / `#` / 출처 URL) 3줄만 표시에서 빼고, URL은 `원문 열기`로 옮긴다. 다른 `#`·URL은 그대로 둔다. 아카라이브 front-matter의 `url`도 원문 링크가 된다.

## 4.1 본문 아래 목록 (들어온 목록)

본문 끝 카드 바로 아래, 댓글보다 위에 **이 독서 세션이 시작된 목록**을 보여 준다(구 DSOTM `BoardMiniList` 계승).

- 어떤 목록인지는 본문 history entry의 `redstmParent`(들어온 경로)에서 정한다. 그래서 새로고침·앞으로가기·딥링크에서도 같다.
  - `/search?q=…` → 그 검색 결과(검색어·게시판·형식·대상·결합 방식 그대로), `/browse?…` → 그 게시판·형식·정렬
  - `/collections/N` → 작품 목차, `/saved?view=…` → 보관함의 그 탭, 홈 `최근 읽은 글` → 최근 읽음, 홈 최근 게시 글 → 전체 최신 글
  - 딥링크(합성 부모) → 그 글의 게시판
  - 텍스트 → 보던 회차·글 목록 그대로(표시 정렬·검색 필터 포함). 텍스트 목록 정렬은 URL `sort`로 남아 새로고침에도 유지된다
- 넓은 화면에서 옆 목록이 보이는 동안에는 같은 목록이므로 숨긴다. 옆 목록에서 다른 글을 고르는 것도 같은 세션 안의 이동(replace)이다(텍스트 포함).
- 10개씩, 처음에는 **현재 글이 들어 있는 페이지**를 연다. 현재 글은 강조하고 목록에 없으면 그렇게 알린다. `이전/다음`으로 페이지를 넘기고, 행을 누르면 같은 세션 안에서 이동(replace)하므로 Back은 여전히 원래 목록이다. `전체 목록`은 `목록` 버튼과 같다.
- 타입문넷의 연재 소속이 아닌 글은 `이전/다음 글`도 이 목록 순서를 따른다(검색 워커 `page` 메시지가 현재 글의 앞뒤 글을 함께 준다). 연재 편·텍스트 회차는 기존대로 정규 순서다.

## 4.2 텍스트 장서 동등성

- 목록 정렬은 보이는 칩(`오래된순/최신순/이름순`, 작품 목록은 `가나다순/편수 많은순/최신 화순`)으로 바꾸며 URL `sort`에 남는다.
- 작품 행은 `작가 · N화 · 읽음 x/N · 최근 M화`, 회차 목록 상태줄은 `작품 · 작가 · N화 · 읽음 x/N`.
- 검색창 안내는 화면별(회차 찾기 / 작품·작가 / 저장한 자료·메모·태그 / 게시판·분류·글 제목).
- 텍스트 저장에도 메모·태그(더보기 `메모·태그`, 타입문넷과 같은 편집기). 저장함 행에 태그·메모가 보이고 검색된다.
- 홈 `읽던 작품`에 읽는 중인 텍스트 소설이 타입문넷 작품과 함께 최근순으로 나온다.
- 아카라이브 내보내기 형식: `[image] URL` → 이미지, `[video] URL` → 누르면 재생하는 영상(`preload=none`, CSP `media-src 'self' https:` 추가), `[라벨](https://unsafelink.com/실제주소)` → 라벨 링크(래퍼 제거). 아카라이브 이미지 CDN은 서명 URL(`expires`)만 허용하고 내보낸 파일의 서명은 이미 만료(410/403)되므로, 만료된 링크는 불러오지 않는다(서명을 떼거나 `expires`만 지운 주소도 403과 함께 200×200 접근 거부 이미지를 준다 — 2026-09-27 실측).
- 아카라이브 이미지 보관(영상 제외): 뉴토미가 받아 전처리한 이미지가 R2 `media/arca/<CDN 경로 키>`에 있다. Reader는 텍스트 본문의 아카라이브 이미지 경로 키(`20230607sac/<해시>.webp`)를 `POST /api/v1/text/media/resolve`로 확인해 보관본(`/api/v1/text/media/arca/<경로 키>`)으로 바꾸고, 없으면 원본(서명이 살아 있을 때) 또는 `만료된 이미지 링크 · 원문 글에서 보기`를 그대로 둔다. 수집·전송·백필 계약은 [`20_arcalive_media_archive.md`](20_arcalive_media_archive.md).

## 4.3 읽는 동안 도구 접기

- 모든 화면 폭(휴대폰·태블릿·PC)과 TypeMoon·텍스트 장서 공통. 본문을 아래로 48px 읽으면 상단(모바일 context bar, PC·태블릿 읽기 도구줄)과 하단 도구가 함께 접힌다.
- 다시 보이기: 멈춘 채 본문을 짧게 탭(같은 탭으로 다시 접힘), 위로 96px 이상 스크롤(몇 줄 되돌려 읽기로는 나오지 않음), 본문 끝의 다음 글 카드에 닿음, 맨 위 80px 안, 키보드 포커스, PC에서 마우스를 본문 위쪽 64px로 가져감. 마우스 클릭은 텍스트 선택용이라 토글하지 않는다.
- 링크·버튼·이미지·다음 글 카드·본문 아래 목록의 탭, 스크롤 끝의 pointerup, 텍스트 선택, 앱이 위치를 복원하며 생긴 스크롤은 토글/숨김으로 치지 않는다.
- 접힌 동안에도 맨 위 진행 선과 오른쪽 아래 작은 `N%` 표시는 남는다(집중 모드에서는 숨김).
- 기기의 "애니메이션 줄이기"(삼성 "애니메이션 제거" 포함)에서도 똑같이 접히고, 미끄러지는 효과만 없다. 이전에는 이 설정이나 760px 이상 폭에서 도구가 항상 떠 있었다.

## 4.4 읽기 도구 보강 (2026-09-28)

- 읽는 시간: 소설·일반 본문 메타 줄 끝에 `약 N분`(공백 제외 500자/분, 1분 미만은 1분, 60분 이상은 `약 N시간 M분`). AA 본문은 그림이라 표시하지 않는다. 계산은 `reading-model.js`의 순수 함수.
- 더보기 `읽은 위치` 옆에 `남은 시간 약 N분` / `1분 안에 끝` / `끝까지 읽음`(95% 이상)을 보이고, 위치 슬라이더를 움직이면 같이 바뀐다.
- `링크 복사`: 지금 주소(타입문넷 `/read/…`, 텍스트 `/text?…`)를 클립보드에 넣고 `링크를 복사했습니다`를 잠깐 띄운다. 클립보드를 못 쓰면 공유 시트(`navigator.share`)로, 둘 다 없으면 실패를 알린다.
- `화면 켜 두기`: Screen Wake Lock을 쓰는 토글(지원 브라우저에서만 보임, 기본 꺼짐, 저장하지 않음). 본문이 열려 있는 동안만 유지하고, 탭이 가려지면 브라우저가 놓으므로 돌아올 때 다시 요청한다. 본문을 닫으면 해제한다. DSOTM의 자동 wake lock은 계속 쓰지 않는다(`09 §7`).
- 이미지 보기: 화면보다 큰 그림에는 `실제 크기` 단추가 생긴다. 그림이나 단추를 누르면 원래 픽셀 크기로 바꾸고 누른 지점(단추는 가운데)을 화면 가운데에 맞추며, 스크롤로 옮겨 본다. 다시 누르면 `화면에 맞춤`. 작은 그림에는 단추가 없다.
- AA `맞춤`(AA 도구줄 zoom 묶음 맨 앞): 그림의 가장 넓은 줄이 가로 스크롤 없이 들어오는 배율로 줄인다. 100%를 넘겨 키우지 않고, 이미 들어오는 그림은 100%로 돌아간다. 배율은 기존과 같은 전역 `aaZoom`이다.
- 홈 `이어서 읽기` 카드 아래쪽에 읽은 만큼의 red 진행 조각(3px)을 그린다(`DESIGN.md §3`의 red 사용 지도).
- 760px 이상에서 `?`는 읽기 설정을 열고 `키보드 단축키` 목록을 펼친다. 휴대폰 폭에서는 목록을 숨긴다.
- 홈 `자주 보는 게시판`: 게시판 선택 시트의 즐겨찾기 → 최근 본 게시판 순서로 최대 8개 chip. 현재 release에 없는 게시판은 빼고, 누르면 형식·검색 조건을 초기화한 채 그 게시판 전체를 둘러보기로 연다.

## 4.5 발견과 한 손 읽기 (2026-09-28 2차)

- 읽기 프로필(P6-2): 퀵 설정에서 현재 산문 설정을 이름으로 저장하고 전환한다. `이 작품만`은 작품을 다시 열 때 그 프로필을 적용하며 기본 설정은 따로 보존한다. 예외를 해제하면 기본 설정으로 돌아간다. 프로필과 작품별 선택은 백업에 포함한다.
- 자동 스크롤(P6-2): 더보기에서 켜면 속도 1–10의 바가 도크 자리를 쓴다. 본문 터치·휠·키 입력, 찾기 열기, 탭이 가려짐은 일시정지한다. 찾기를 닫으면 멈춘 바가 돌아오고, Reader 종료·회차 이동은 자동 스크롤을 끈다. 페이지 모드·AA에는 제공하지 않는다.

- 정렬: 목록 건수 옆 `결과 줄`의 정렬 pill(모든 폭, 필터 시트 밖)에서 바로 바꾼다. 글은 최신순·오래된순에 release가 수를 가질 때 `조회 많은순`·`댓글 많은순`, 작품은 최근 글순·가나다순·편수 많은순에 `조회 많은순`·`댓글 많은순`(보존된 편 합계). 수가 없는 release에서는 그 선택지를 숨기고, 링크의 `sort=views`는 작품 색인이 늦게 도착해도 그때 적용된다. 행에는 `조회 2.5만 · 댓글 3`처럼 줄인 수를 보인다.
- 홈 `오늘의 발견`(읽던 작품·자주 보는 게시판 다음):
  - `오늘의 추천 작품`: 아직 읽지 않은 연재(보존 3편 이상, 단편 묶음 제외) 3개. 날짜로 정해져 하루 동안 같고, 수가 있으면 `1 + log10(1 + 조회 + 5×댓글)` 가중치로 인기 작품이 더 자주 나온다. `다른 추천`은 이 탭에서 다른 3개를 뽑는다.
  - `요즘 화제`: 가장 최근 2,000개 글 중 댓글 많은 순 4개(수가 있을 때만).
  - `이날의 기록 · M월 D일`: 예전 해 같은 날짜에 쓴 글 3개(`N년 전`), 화제에 이미 나온 글은 뺀다.
  - 여기서 연 글의 본문 아래 목록은 그 글의 게시판이다.
- 읽던 작품: 가장 멀리 연 편 뒤에 편이 있고 최신 편이 마지막으로 읽은 뒤에 올라왔으면 `새 편` 표시와 함께 맨 앞에 둔다.
- 작성자: 본문 메타의 작성자 이름을 누르면 그 작성자의 글 검색(`target=author`)을 연다. 휴대폰 키보드는 올리지 않는다.
- 두 손가락: 소설·텍스트 본문을 벌리거나 모으면 글자 크기가 1px 단위로 바뀌고(15–28px) 화면 맨 위 문장을 유지한다. 이 때문에 본문은 브라우저 pinch 확대를 쓰지 않는다(`touch-action: pan-x pan-y`, 이미지는 눌러서 이미지 보기). AA는 기존대로 그림 배율이다.
- `화면 탭으로 넘기기`(설정 → 읽기 동작, 기본 끄기): 켜면 멈춘 탭이 화면 위 25%면 한 화면 위로, 아래 40%면 한 화면 아래로(두 줄 겹침) 넘기고 가운데는 도구를 토글한다. 앞으로 넘길 때 도구를 접고, 넘기는 스크롤은 도구를 다시 부르지 않는다.
- 설치 앱: `앱으로 설치`(브라우저가 설치 가능하다고 알릴 때만 설정에 보임). manifest `shortcuts`로 아이콘 길게 누르기 → 이어서 읽기(`/?continue=1`, 저장 기록을 색인에 맞춘 뒤 이어서 읽기 카드와 같이 열어 Back은 홈)·검색·보관함·텍스트 장서.

## 5. 설정

- 순서: 배경(시스템/밝게/어둡게 segmented, 본문 면 기본/종이) → 글자 크기(`가`/`가` 단계 버튼 + 슬라이더, 15–28px) → 줄 간격 → 좌우 여백(모바일, 12–32px, 기본 20) / 본문 너비(데스크톱) → 서체 → 문단 정렬(왼쪽 맞춤/양쪽 맞춤) → AA → 앱과 기록(운영 현황, 기록 내보내기/가져오기).
- 본문 면 `종이`는 Reader에만 적용하는 따뜻한 면이다(색은 `DESIGN.md §3`). 문단 정렬은 소설·일반·텍스트 본문에만 적용하고 AA는 원본 정렬을 유지한다. 정렬을 바꿀 때도 화면 맨 위 문장을 유지한다.
- 세 값은 user-state v2 `settings.readerSurface`(`default|paper`)·`settings.proseAlign`(`start|justify`)·`settings.tapPaging`(`off|on`)이다.
  - 2026-09-30 개편(P1-4): `readerSurface`에 `ink`(먹, 앱 테마와 무관한 검은 면) 추가, `settings.readerDim`(밝기 낮추기 0–60%)·`settings.readerWarm`(따뜻하게 0–25%) 추가. 둘은 글자를 다시 배치하지 않는 화면 overlay다. 색은 `DESIGN.md §2.4`. 없는 기존 파일은 기본값으로 보정되고 가져오기 미리보기의 `기본값 보정`에 이름이 나온다(스키마 버전 변화 없음).
  - 2026-10-01 개편(P2-2): `settings.paragraphSpacing`(문단 간격 0–2em, 기본 0.95)·`settings.textIndent`(들여쓰기 0–2em, 기본 0)는 산문에만 적용하고 AA에는 닿지 않는다. `settings.homeQuote`(`on|off`, 기본 on)는 서재 이어 읽기 카드의 마지막 문장 줄. 도크 `Aa`는 퀵 설정 패널을 열고 `모든 설정`에서 이 시트로 온다.
  - 2026-10-01 개편(P2-3): `settings.readingMode`(`scroll|page`, 기본 scroll). 페이지는 산문 본문을 한 쪽 폭의 CSS columns로 배치하고 transform으로 넘긴다(scroll-snap 없음). 탭 영역 오른손(왼쪽 30% 이전 · 가운데 20% 도구 · 오른쪽 50% 다음), 쪽 끝을 넘기면 다음/이전 화, 가장자리 24px 스와이프는 시스템 Back 몫. 키보드 ←/→·Space·PageUp/Down·Home/End. 위치는 스크롤과 같은 문장 locator로 저장하며 쪽 번호는 파생값이다(저장 `scroll`은 페이지 모드에서 처음 쪽이면 0). 머리·본문 끝 카드·댓글은 스크롤 방식에서만 보이고, AA 글은 스크롤로 보여 준다(안내 1회).
- 글자 크기·줄 간격·여백·서체를 바꿔도 **화면 맨 위 문장이 그대로** 남는다(`public/text-anchor.js`, 레이아웃 기하 기반이라 시트가 열려 있어도 동작). 텍스트 본문의 읽기 위치도 같은 문자 anchor로 저장한다.
- 사용자 상태 스키마는 그대로(v2 / text v1). `proseSize` 상한 24→28, `proseMargin` 추가는 범위를 넓히는 변경이라 기존 파일이 그대로 유효하다.

## 6. 게시판 선택과 필터

- 게시판은 일반 필터에서 분리된 **게시판 바**(모바일: 목록 아래·하단 탭 위, 넓은 화면: 탭 아래)에서 고른다. 시트에는 검색, 즐겨찾기(★, 행 선택과 별도 버튼), 최근 본 게시판 4개, release `group_name` 기준 접이식 그룹이 있다. 그룹 제목은 펼치기/접기만 한다.
- 고르면 즉시 그 게시판만 보인다. 선택한 게시판을 숨기는 형식(AA/소설) 조건은 풀고 상태줄에 알린다. `×`로 전체 게시판.
- 즐겨찾기·최근·펼침은 `redstm.boardNav.v1`(이 브라우저, 상태 내보내기에 포함되지 않음).
- 모바일 필터 시트는 **임시값 + 적용**: 적용 전에는 목록이 바뀌지 않고 X·Esc·Back은 취소한다. `전체 초기화` 중복 버튼은 없앴다. 읽기 설정은 즉시 반영이다. 정렬은 2026-09-28부터 시트 밖 결과 줄에 있고 즉시 반영된다(§4.5).

## 9. 텍스트 장서 편의 기능 (2026-09-29)

TypeMoon 쪽에만 있던 읽기 편의를 텍스트 장서(소설·아카라이브)에도 연결했다. 읽기 기록은 계속 `redstm.textState.v1`에 있고 새 저장소를 만들지 않는다.

- **백업**: `기록 내보내기`가 schema 2 파일에 선택 필드 `text`(텍스트 읽기 기록·저장·메모·태그)를 함께 쓴다. `sanitizeTextState`가 identity(`novel:`/`arcalive:`), 시각, 해시, `/text?` 경로만 통과시킨다. `text`가 없는 예전 파일을 가져오면 이 브라우저의 텍스트 기록은 그대로 둔다. localStorage의 TypeMoon 상태에는 `text`를 넣지 않는다.
- **새 회차**: 회차를 열 때 기록하는 `total`(그때의 작품 편수)의 최댓값보다 지금 `chapter_count`가 크면 `새 N화`다. 작품 목록 줄, 홈 `읽던 작품`(TypeMoon `새 편`과 같은 우선 정렬), 보관함 `읽는 중`에 표시한다. 홈은 읽던 소설이 있고 소설 목록을 아직 받지 않았으면 목록을 받아 온다(내용 주소라 브라우저 캐시를 탄다).
- **읽기 상태 칩**: 소설 작품 목록에 `전체·읽는 중·새 회차·안 읽음·다 읽음`(건수 포함). URL `read=`로 유지되고 목차 안에서는 숨는다. 작품 정렬에 `최근 읽은순`을 더했다.
- **이전 회차 모두 읽음**: 더보기에서 지금 회차 앞의 안 읽은 회차를 다 읽음으로 표시한다(다른 곳에서 읽던 작품). 새 기록의 읽은 시각은 지금 회차보다 앞이라 이어 읽기 대상은 바뀌지 않는다.
- **아카라이브 분류 안 글**: `최신순`(기본)·`오래된순`·`제목순`. 전에는 수입 순서였고 정렬이 적용되지 않았다. 이전/다음 글은 목록 정렬과 무관하게 글 번호 순서다(§3의 목록 정렬 원칙).
- **검색 → 텍스트 장서**: TypeMoon 검색 결과가 없으면 같은 검색어로 `소설에서 찾기`·`아카라이브 작품에서 찾기`를 제공한다.
- **보관함 통합**: `저장한 글`에 텍스트 저장 항목(메모 포함, 검색어 적용)을, `읽는 중`에 읽던 소설을 함께 보여 준다. 누르면 텍스트 장서의 해당 목록/본문으로 열리고 Back은 보관함으로 돌아온다.

검증(로컬): `npm test`, `npm run check`, Playwright `reader-flow.spec.js` 새 테스트 5개(새 회차·칩·홈 배지, 이전 회차 읽음, 분류 글 정렬과 읽기 순서, 검색→텍스트, 보관함 통합)와 전체 4개 프로젝트.

## 10. 텍스트 작품 목록·긴 목록·AA 배율·접근성 검사 (2026-09-30)

**텍스트 장서를 TypeMoon 작품 목록처럼**
- 작품 줄: 출처(소설은 북토끼·블랙툰·마루마루 등, 아카라이브는 게시판) · 작가 · `읽은 수/전체` · 다음 행동(`시작하기`/`이어 읽기`/`다시 보기`) · `최신 N화` · 갱신일, `새 N화` 배지. 기본 정렬은 TypeMoon `최근 글순`과 같은 `최근 갱신순`이고 `가나다순·편수 많은순·최근 읽은순`을 고른다. 소설은 `출처` 선택(2개 이상일 때)이 URL `source=`로 유지된다.
- 회차 목록 머리: 작품 제목, 출처·작가·편수·최신 회차·갱신일·읽음 수, 11화 이상이면 `몇 화?` 이동(라벨 숫자 우선, 없으면 읽기 순서 N번째).
- 아카라이브 작품별도 같은 읽기 상태 칩·진행·정렬을 쓴다. publisher가 작품 목록에 `post_ids`(읽기 순서)를 싣고, Reader는 `arcalive:<board>:<post_id>:text` 기록으로 게시판 폴더에서 읽은 글도 작품 진행에 센다. `post_ids`가 없는 이전 게시본은 작품 안에서 연 기록(`workId`)만 센다.
- 분류 위(전체·게시판)에서 검색하면 폴더 대신 맞는 글을 최신순으로 바로 보여 준다. 이전/다음 글은 그 결과의 글 번호 순서다.
- 검색어는 제목에서 표시(mark)한다. 상태줄은 `N개 작품/게시판/분류/글`로 무엇을 세는지 말한다.

**긴 목록**: 텍스트 목록은 400줄씩 그리고, 끝 표지가 화면 1200px 안에 들어오면 다음 400줄을 붙인다(IntersectionObserver). 목록 위치 복원·`몇 화?`는 필요한 줄까지 먼저 그린다. 측정(로컬 Chrome): 아카라이브 1만 글 분류 열기 2.6s→0.34s, 정렬 변경 0.88s→0.04s, 3천 회차 작품 0.38s→0.17s. TypeMoon 결과 목록은 이미 `더 보기` 페이지 단위이고, 작품 목차(3천 편 0.78s)는 실제 규모에서 문제가 없어 그대로 둔다.

**AA 배율**: 본문 도구줄에는 배율(`맞춤 · − · % · +`)과 `색`(원본색 ↔ 단색)만 둔다. 두 손가락은 움직이는 동안 그림만 확대·축소하고 손을 떼면 그 배율(10–300%, 연속값)로 다시 그린다. 한 번 탭은 도구를 바로 보이거나 숨기고, 300ms 안에 한 번 더 탭하면 그것을 되돌리고 `맞춤 ↔ 100%`를 바꾼다. `−`/`+`는 지금 화면의 배율에서 25%씩 움직인다. 글자 크기는 설정의 `AA 기본 크기`와 프리셋에 남는다. 배율과 가로 위치는 글마다 `aaViews`(최근 300개, 백업 포함)에 기억해 다시 열면 이어진다. 설정 `넓은 AA 화면에 맞추기`를 켜면 저장된 배율이 없는 글은 열 때 화면 너비에 맞추되 그 맞춤은 저장하지 않는다. 프리셋은 열린 글의 배율도 초기화한다.

**접근성 자동 검사**: `e2e/a11y.spec.js`가 axe-core(WCAG 2.1 A/AA)로 홈·둘러보기·검색·작품 목차·보관함·Reader·설정·더보기·텍스트 목록/회차/본문·아카라이브 작품·어두운 테마·운영 화면을 4개 폭에서 검사한다. 처음 실행에서 나온 위반은 두 가지였다. 밝은 테마 accent `#D92D3D`가 accent-soft·page 위에서 4.35–4.49:1이라 `#D12A3A`(4.66–5.12:1)로 조정했다(`DESIGN.md`). 운영 화면 `<dl>` 안 설명 `<small>`은 `dd.kpi-note`로 바꿨다. 사람이 판단할 항목(읽기 순서, 이름의 의미)은 수동 검토로 남는다.

검증(로컬): `npm test` 103, `npm run check`, Playwright 전체 502 passed(14 skipped), pytest·ruff·mypy.

## 11. 소설 개인 분류와 백업 v3 (2026-09-30)

**개인 분류(소설)**: 작품마다 분류 하나(폴더). 기록은 `redstm.textState.v1`의 `shelves`
(`{id, name, hidden}` 순서 목록, 최대 50)와 `workShelves`(`work_id → shelf id`)이며 모델은
`public/text-shelves.js`(단위 테스트 `test/text-shelves.test.js`)다.
- 처음 쓸 때 `찜 · 나중에 볼 작품`, `다 본 작품`, `안 볼 작품`(숨김)을 만든다. 이름 바꾸기·숨기기·순서·삭제가 되고,
  지운 분류의 작품은 미분류로 돌아간다. 이름은 대소문자 무시 중복 불가, 30자.
- 소설 탭 `전체 목록`은 숨긴 분류의 작품을 빼고 상태줄에 `숨긴 분류 N개 제외`를 붙인다. `분류별`은 미분류와
  각 분류를 폴더(작품 수, 숨김 표시)로 보여 주고 폴더 안에서는 정렬·읽기 상태 칩이 그대로 적용된다.
  URL: `view=shelves`, `shelf=<id|unsorted>`.
- 작품 줄 오른쪽 `분류` 단추(지정된 분류 이름 표시)와 회차 목록 머리의 `분류: …` 단추가 같은 대화상자를 연다.
  작품을 분류하던 중 새로 만든 분류에는 그 작품이 바로 들어간다. `분류 관리`는 작품 없이 목록만 관리한다.
- 작품이 새 canonical ID로 바뀌면(`legacy_work_ids`) 분류가 따라간다.

**백업 v3**: `기록 내보내기`는 `{format: "redstm-backup", schema_version: 3, exported_at, typemoon, text}`를
쓴다. `typemoon`은 v2 상태(설정·기록·저장·위치·보기·AA 보기), `text`는 텍스트 기록·저장·분류다. v1·v2 파일도
가져온다. 가져오기 검토에서 두 가지를 고른다.
- `합쳐서 가져오기`(기본): 글마다 더 최근 읽기 기록을 남기고 진행률은 큰 값, 저장·보기·AA 보기·분류는 합친다
  (같은 이름의 분류는 하나로). 이 브라우저의 설정은 유지한다. 여러 기기의 기록을 모을 때 쓴다.
- `덮어쓰기`: 이 브라우저의 기록과 설정을 파일 내용으로 바꾼다(텍스트 부분은 파일에 있을 때만).

**백업 v4**(2026-10-01, docs/24 P3-5): 이 기기에 계정 저장소(`redstm:<ownerHash>`)가 있으면 `records`
(`annotations` 표시·메모 — 지운 기록의 tombstone 포함, `sessions` 독서 세션)를 더해 `schema_version: 4`로 쓰고,
브라우저가 지원하면 gzip으로 압축한 `.json.gz`로 내려받는다(없으면 v3 형식 그대로, 압축 미지원이면 `.json`).
가져오기는 gzip과 평문 JSON, v1–v4를 모두 받는다. 표시·메모·독서 기록은 `덮어쓰기`여도 항상 합친다:
한쪽이라도 지운 기록은 지운 채로 두고(되살리지 않음), 아니면 나중에 고친 쪽이 이긴다. 세션은 같은 id면 더 멀리 간 쪽.
한 트랜잭션으로 쓰므로 저장이 실패하면 기존 기록은 그대로다. 계정 저장소가 없는 기기에서는 그 부분을 가져오지 못했다고 알린다.
시각은 글자가 아니라 같은 순간으로 비교하며, 시간대 오프셋이 붙은 시각은 가져올 때 같은 순간의 UTC로 바꿔 둔다
(R01: `09:00+09:00`이 같은 날 `00:30Z`보다 이전).

## 12. 텍스트 장서 동선 정리와 로컬 기록 크기 (2026-09-30)

- **정렬**: 텍스트 목록도 TypeMoon처럼 결과 줄 오른쪽 정렬 메뉴를 쓴다. 따로 있던 정렬 칩 줄을 없애 휴대폰에서 목록이
  한 줄 먼저 보인다. 읽기 상태 칩과 출처 선택은 가로로 넘기는 한 줄이다.
- **작품 머리**: 작품을 열면 `← 작품 목록` 바로 아래에 제목·출처·작가·편수·갱신·읽음 수, 그 아래 한 줄에
  `분류: …`와 `몇 화?`가 온다(검색창과 상태줄은 그 아래). 작품 안에서는 `전체 목록/분류별/분류 관리` 탭을 숨긴다.
- **작품 줄의 분류 단추**는 5.5rem까지로 줄여 긴 제목의 줄바꿈을 덜었다.
- **다시 그리기**: 목록을 다시 그려도 초점이 있던 줄에 초점이 남고, 이미 보이는 검색어에 대한 늦은(debounce)
  알림은 목록·작품 머리를 다시 만들지 않는다(입력 중이던 `몇 화?` 값이 사라지던 것).
- **로컬 기록 크기**: 텍스트 기록 한 건은 경로·제목·위치까지 ~800자라 1만 건이면 브라우저 localStorage
  한도(~5MB, TypeMoon 상태와 공유)를 넘었다. 작품별 최신 기록과 최근 50건만 세부(경로·제목·정확한 위치)를
  두고, 나머지는 읽은 시각·진행률만(안 끝난 회차는 위치도) 남긴다. 텍스트 상태 전체는 150만 자 안으로 유지하고
  넘치면 오래된 읽기 기록부터 지운다(저장한 글·분류는 유지). 최대 상태의 백업 파일은 수 MB다.


## 13. 작품 안 찾기 (P6-3, 2026-10-02)

TypeMoon·소설·아카라이브 작품 상세의 `작품에서 찾기`, Reader 더보기, 본문 찾기의 `작품 전체`, 선택 문장 메뉴에서 같은 KWIC 시트를 연다. 기본 범위는 실제 열어 본 회차와 지금 읽는 회차이며, 나중 회차를 잠깐 방문했다고 사이 회차를 읽은 것으로 보지 않는다. `작품 전체 (안 읽은 회차 포함)`을 직접 켜야 범위를 넓힌다. 진행·확인 못 한 회차·결과 분포·취소를 표시한다.

결과는 원문 문장 locator로 열며, Back은 검색어·범위를 담은 작품 경로로 돌아가 검색 결과를 다시 보여 준다. 텍스트 작품의 기존 정렬 조건도 유지한다. 작품에 속하지 않는 글에는 이전 작품의 검색 범위를 재사용하지 않는다. 폰의 키보드와 시스템 Back 확인은 §14.5 M6 확인 대기다.

## 14. 스마트 서재·분류·명령 팔레트 (P6-4, 2026-10-02)

Ctrl/Cmd+K는 작품·작가와 화면 이동·설정·Reader 명령을 찾는다. TypeMoon·소설·아카라이브 메타데이터에 같은 초성·자모 검색을 쓰며, IME 조합 중 단축키는 실행하지 않는다. ↑↓·Enter로 결과를 열고 Escape로 닫는다. 일반 검색의 작품 제안에도 텍스트 작품을 포함한다.

서재의 스마트 서재는 출처·읽기 상태·새 화·AA·분류·고정·최대 회차 수를 모두 만족하는 작품 보기다. 조건 조합에 이름을 붙여 저장·수정·삭제할 수 있다. 세 출처 작품 상세와 Reader에서 같은 분류·고정 시트를 열며 고정 작품은 서재 표지 서가에 표시한다. 분류 삭제는 작품을 미분류로 남긴다.

검증된 계정의 IndexedDB에 분류·보기(`meta.library`)와 작품 정보(`works`)를 한 트랜잭션으로 기록한다. 기존 소설 분류는 첫 저장 때 포함하며 원본 localStorage는 보존한다. v4 백업은 두 기록도 포함하고 나중 수정 시각으로 병합한다. 이전 v4 백업에 선택 필드가 없으면 현재 설정을 지우지 않는다. 서버 동기화는 하지 않는다. 실기기 Ctrl/Cmd+K·IME·시스템 Back은 §14.5 M6 확인 대기다.

## 15. 이어 스크롤 (P6-5, 2026-10-02)

읽기 설정의 `이어 스크롤`은 TypeMoon·소설·아카라이브 연재 산문에서 다음 회차를 본문 아래에 표시한다. 미리보기만으로 읽은 기록을 만들지 않고, 그 회차가 화면 위쪽에 들어오면 현재 Reader 문서로 전환한다. 이전·현재·다음 DOM은 합쳐 최대 세 회차이며 현재 문서는 기존 `archive-body` ID를 유지한다. 앞 회차를 제거할 때도 보이는 문장의 화면 위치를 유지한다.

뒤로 스크롤하면 보관한 이전 회차를 다시 현재 문서로 연다. 각 회차의 원문 locator·진행률·주석·통계는 따로 기록하며, 회차 이동은 같은 history entry를 교체하므로 한 번의 Back은 목록 복귀다. 큰 스크롤로 원문의 마지막 줄을 지나면 그 문서의 끝 locator를 저장한다. AA와 작품에 속하지 않는 글은 기존 스크롤 방식이다. 실기기 플릭·늦은 이미지/글꼴·키보드/Back 확인은 §14.5 M6 대기다.

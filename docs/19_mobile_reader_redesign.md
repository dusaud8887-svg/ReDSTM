# 모바일 읽기 경험 개편 — 구현 계약

- 상태: Repository target (브랜치 `frontend-mobile-reader-redesign`, 미배포)
- 기준일: 2026-09-27
- 입력 명세: [`개선/ReDSTM_Mobile_UX_Frontend_Redesign_Spec.md`](개선/ReDSTM_Mobile_UX_Frontend_Redesign_Spec.md)
- 대체하는 계약: `15`의 Reader 이동·뒤로가기·설정 배치 중 아래 §7에 적은 항목

이 문서는 명세 중 **실제로 구현하고 테스트로 고정한 것**만 적는다. 명세의 나머지 항목은 §8 후속으로 남긴다.

## 1. 한 번의 독서 세션 = history entry 하나

| 행동 | history |
|---|---|
| 목록·홈·목차에서 본문 열기 | push 1회 (`redstmReader`, `redstmParent=<열었던 목록 경로>`) |
| 이전/다음, 본문 끝 다음 편, 옆 목록에서 다른 행 선택(데스크톱) | replace |
| 시스템 Back / 상단 `‹ 목록` / 하단 `목록` / 본문 끝 `목록으로` | 모두 같은 동작: parent가 있으면 `history.back()` |
| 본문 → `작품 목차` | 그 목차에서 들어왔으면 back, 아니면 목차가 본문 entry를 replace |
| 홈 `이어서 읽기`(작품 소속) | 목차 entry를 먼저 쌓고 본문 push → Back 순서: 본문 → 목차 → 홈 |
| 직접 링크(`/read/…`, `/collections/…`, `/text?…&chapter=`) | 첫 진입에 한 번만 부모 목록을 합성(게시판 목록 / 작품 목록 / 회차 목록). 새로고침으로 다시 쌓이지 않음 |

텍스트 장서(소설·아카라이브)도 같은 규칙을 쓴다. 목록 단계(작품→회차, 게시판→분류→글)는 단계마다 push하고, `← 작품 목록`은 부모가 바로 아래 entry면 back이다.

## 2. 회차 순서는 목록 정렬과 무관하다

- 타입문넷 작품: 작품 `position` 순. 보존되지 않은 편은 건너뛰되 본문 끝 카드에 `N편은 보존되지 않아 M편으로 이어집니다`를 표시.
- 텍스트 소설: 회차 파서의 오래된순(정규 순서). 목록을 최신순·이름순으로 보여도 `다음 화`는 항상 다음 회차. 저장함에서 연 회차도 작품 목차를 불러와 순서를 가진다.
- 아카라이브·작품에 속하지 않은 글: 본문을 연 순간의 목록 순서를 고정해 `이전 글/다음 글`로 이동.
- 현재 항목을 순서에서 찾지 못하면 이동하지 않는다(다른 글로 대체하지 않음). 순수 함수 `public/sequence.js`.

## 3. 목록 위치 복원

- 목록 행마다 안정 키(`data-key`: 글 identity, `collection:<id>`, 편 번호, `chapter:<id>`, `work:<id>`)를 둔다.
- 떠날 때 **맨 위에 보이던 행과 그 오프셋**을 저장하고, 돌아오면 그 행을 같은 오프셋에 맞춘다(`public/list-anchor.js`). 읽음 배지 등으로 위쪽 행 높이가 바뀌어도 화면이 밀리지 않는다.
- 결과 목록은 기존 `lastCatalogState`(불러온 개수·포커스)에 anchor를 더했고, 작품 목차와 텍스트 목록은 경로별 snapshot(sessionStorage, 최근 40개)을 쓴다.
- 목차에서 마지막으로 읽은 편은 강조(`current`), 텍스트 회차 목록 맨 위에는 `이어 읽기 · N화` 행이 생긴다.
- 긴 작품 목차에는 `회차로 이동`(번호 입력 → 가장 가까운 편 행으로 이동, 열지는 않음).

## 4. 공통 Reader

- 타입문넷과 텍스트가 **같은 DOM**을 쓴다(`#reader`, `data-source`). 텍스트 전용 뷰어는 제거했다.
- 모바일 하단: `목록 | 이전 | 다음 | Aa 설정 | 더보기`. 이전·다음이 붙어 있고 다음이 가장 넓고 강조된다. 저장은 상단 context bar 오른쪽과 더보기에 있다.
- 모바일 상단: 앱 바 대신 `‹ 목록 · 작품명 N/M · 저장` context bar. 아래로 읽으면 상·하단 도구가 함께 숨고, 위로 스크롤하거나 본문을 짧게 탭하면 다시 나온다. 스크롤 끝의 pointerup이나 앱이 위치를 복원하며 생긴 스크롤은 탭/숨김으로 치지 않는다.
- 본문 끝 카드(댓글보다 먼저): 다음 편/화 제목이 적힌 큰 버튼 → `목록으로`·`작품 목차` → 작게 이전 편. 마지막이면 `작품 목차로 돌아가기`/`회차 목록으로`. 본문 끝 카드로 넘기면 현재 편을 완독 처리하고, 하단 `다음`은 완독 처리하지 않는다.
- 더보기 시트(모든 폭, 데스크톱은 도구줄 `⋯`): 작품 목차 · 저장 · 메모·태그(타입문넷) · 원문 열기 · AA/소설 보기 · 집중 모드. 가능한 항목만 보인다.
- 진행률은 본문 끝 기준이다(긴 댓글이 완독을 막지 않음).
- 텍스트 소설 본문 앞의 수집 wrapper(`# 제목` / `#` / 출처 URL) 3줄만 표시에서 빼고, URL은 `원문 열기`로 옮긴다. 다른 `#`·URL은 그대로 둔다. 아카라이브 front-matter의 `url`도 원문 링크가 된다.

## 5. 설정

- 순서: 배경(시스템/밝게/어둡게 segmented) → 글자 크기(`가`/`가` 단계 버튼 + 슬라이더, 15–28px) → 줄 간격 → 좌우 여백(모바일, 12–32px, 기본 20) / 본문 너비(데스크톱) → 서체 → AA → 앱과 기록(운영 현황, 기록 내보내기/가져오기).
- 글자 크기·줄 간격·여백·서체를 바꿔도 **화면 맨 위 문장이 그대로** 남는다(`public/text-anchor.js`, 레이아웃 기하 기반이라 시트가 열려 있어도 동작). 텍스트 본문의 읽기 위치도 같은 문자 anchor로 저장한다.
- 사용자 상태 스키마는 그대로(v2 / text v1). `proseSize` 상한 24→28, `proseMargin` 추가는 범위를 넓히는 변경이라 기존 파일이 그대로 유효하다.

## 6. 게시판 선택과 필터

- 게시판은 일반 필터에서 분리된 **게시판 바**(모바일: 목록 아래·하단 탭 위, 넓은 화면: 탭 아래)에서 고른다. 시트에는 검색, 즐겨찾기(★, 행 선택과 별도 버튼), 최근 본 게시판 4개, release `group_name` 기준 접이식 그룹이 있다. 그룹 제목은 펼치기/접기만 한다.
- 고르면 즉시 그 게시판만 보인다. 선택한 게시판을 숨기는 형식(AA/소설) 조건은 풀고 상태줄에 알린다. `×`로 전체 게시판.
- 즐겨찾기·최근·펼침은 `redstm.boardNav.v1`(이 브라우저, 상태 내보내기에 포함되지 않음).
- 모바일 필터 시트는 **임시값 + 적용**: 적용 전에는 목록이 바뀌지 않고 X·Esc·Back은 취소한다. `전체 초기화` 중복 버튼은 없앴다. 읽기 설정은 즉시 반영이다.

## 7. 바뀐 기존 계약

| 기존 | 새 계약 |
|---|---|
| 다음/이전 편마다 history가 쌓이고 Back이 이전 편으로 감 | 회차 이동은 replace, Back은 목록 |
| 직접 링크 Back은 앱 밖 | 합성 부모 목록으로 1회 |
| 텍스트 전용 뷰어(`#text-reader…`) | 공통 Reader |
| 하단 `목록/이전/저장/다음/설정` | `목록/이전/다음/설정/더보기` |
| 읽기 설정 첫 항목 운영 현황, `현재 글` 묶음 | 운영은 설정 맨 아래, 글 동작은 더보기 |
| 테마 select | segmented control (`[data-theme-choice]`) |
| 게시판 select가 필터 안 | 게시판 바 + 시트 (`#board-filter`는 값만 보관) |
| 모바일 읽기 중 앱 바 | Reader context bar |
| 뒤로 와서 검색창 자동 focus | 명시적으로 검색 탭을 누를 때만 focus |

## 8. 검증과 남은 일

검증(로컬, 2026-09-27): `npm test` 77/77, `npm run check` 통과, Playwright 4개 프로젝트(1440/768/390 Pixel 7/320) 전체 통과(필터 시트 테스트는 좁은 화면에서만 실행). 신규 `e2e/reader-flow.spec.js`가 300편 200→201→202→Back 목록 anchor ±4px, 최신순 표시에서도 다음 화=201화, 텍스트 본문 끝 카드, 글자 크기 변경 시 같은 문장, 이미지 표시·실패·뷰어, 회차 이동을 고정한다. S22+ 크기(384×832, DPR 2.8125) 스크린샷으로 화면을 검토했다.

검증하지 못한 것:
- Galaxy S22+ 실기기(삼성 인터넷/Chrome), 제스처 Back, 한손 오탭 기록. 시트·설정·이미지 뷰어의 Android Back은 네이티브 `<dialog>` close request에 맡겼다(별도 history entry 없음) — 실기기 확인 필요.
- 외부 이미지 host의 핫링크 차단 비율. 실패 시 원본 링크로 대체된다.
- 배포는 하지 않았다.

후속(명세에 있으나 이번에 하지 않음): 합성 백업 형식(v3)과 보관함 통합, 텍스트 메모·태그, AA 확대 UX 단순화와 좌표 저장, 목록 가상화, 다음 회차 prefetch, 홈의 텍스트 이어읽기, `@axe-core/playwright` 도입.

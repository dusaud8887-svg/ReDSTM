# 모바일 읽기 경험 개편 — 구현 계약

- 상태: Repository target (브랜치 `frontend-mobile-reader-redesign`, 미배포)
- 기준일: 2026-09-27
- 입력 명세: [`개선/ReDSTM_Mobile_UX_Frontend_Redesign_Spec.md`](개선/ReDSTM_Mobile_UX_Frontend_Redesign_Spec.md)
- 대체하는 계약: `15`의 Reader 이동·뒤로가기·설정 배치 중 아래 §7에 적은 항목

이 문서는 명세 중 **실제로 구현하고 테스트로 고정한 것**만 적는다. 명세의 나머지 항목은 §8 후속으로 남긴다.

## 1. 한 번의 독서 세션 = history entry 하나

| 행동 | history |
|---|---|
| 목록·홈·목차에서 본문 열기 | push 1회 (`redstmReader`, `redstmParent=<열었던 목록 경로>`) |
| 이전/다음, 본문 끝 다음 편, 옆 목록에서 다른 행 선택(데스크톱) | replace |
| 시스템 Back / 상단 `‹ 목록` / 하단 `목록` / 본문 끝 `목록으로` | 모두 같은 동작: parent가 있으면 `history.back()` |
| 본문 → `작품 목차` | 그 목차에서 들어왔으면 back, 아니면 목차가 본문 entry를 replace |
| 홈 `이어서 읽기`(작품 소속) | 목차 entry를 먼저 쌓고 본문 push → Back 순서: 본문 → 목차 → 홈 |
| 직접 링크(`/read/…`, `/collections/…`, `/text?…&chapter=`) | 첫 진입에 한 번만 부모 목록을 합성(게시판 목록 / 작품 목록 / 회차 목록). 새로고침으로 다시 쌓이지 않음 |

텍스트 장서(소설·아카라이브)도 같은 규칙을 쓴다. 목록 단계(작품→회차, 게시판→분류→글)는 단계마다 push하고, `← 작품 목록`은 부모가 바로 아래 entry면 back이다.

## 2. 회차 순서는 목록 정렬과 무관하다

- 타입문넷 작품: 작품 `position` 순. 보존되지 않은 편은 건너뛰되 본문 끝 카드에 `N편은 보존되지 않아 M편으로 이어집니다`를 표시.
- 텍스트 소설: 회차 파서의 오래된순(정규 순서). 목록을 최신순·이름순으로 보여도 `다음 화`는 항상 다음 회차. 저장함에서 연 회차도 작품 목차를 불러와 순서를 가진다.
- 아카라이브·작품에 속하지 않은 글: 본문을 연 순간의 목록 순서를 고정해 `이전 글/다음 글`로 이동.
- 현재 항목을 순서에서 찾지 못하면 이동하지 않는다(다른 글로 대체하지 않음). 순수 함수 `public/sequence.js`.

## 3. 목록 위치 복원

- 목록 행마다 안정 키(`data-key`: 글 identity, `collection:<id>`, 편 번호, `chapter:<id>`, `work:<id>`)를 둔다.
- 떠날 때 **맨 위에 보이던 행과 그 오프셋**을 저장하고, 돌아오면 그 행을 같은 오프셋에 맞춘다(`public/list-anchor.js`). 읽음 배지 등으로 위쪽 행 높이가 바뀌어도 화면이 밀리지 않는다.
- 결과 목록은 기존 `lastCatalogState`(불러온 개수·포커스)에 anchor를 더했고, 작품 목차와 텍스트 목록은 경로별 snapshot(sessionStorage, 최근 40개)을 쓴다.
- 목차에서 마지막으로 읽은 편은 강조(`current`), 텍스트 회차 목록 맨 위에는 `이어 읽기 · N화` 행이 생긴다.
- 홈 `이어서 읽기`는 타입문넷과 텍스트 중 더 최근에 읽은 것을 보여 준다. 텍스트는 Back이 본문 → 회차 목록 → 홈 순서이고, 다 읽은 소설 회차는 곧바로 다음 화를 연다(Back: 다음 화 → 회차 목록 → 홈). 텍스트 기록에 `title/work/route/listRoute`를 함께 저장한다(이전 기록은 다음에 열 때부터 대상).
- 긴 작품 목차에는 `회차로 이동`(번호 입력 → 가장 가까운 편 행으로 이동, 열지는 않음).

## 4. 공통 Reader

- 타입문넷과 텍스트가 **같은 DOM**을 쓴다(`#reader`, `data-source`). 텍스트 전용 뷰어는 제거했다.
- 모바일 하단: `목록 | 이전 | 다음 | Aa 설정 | 더보기`. 이전·다음이 붙어 있고 다음이 가장 넓고 강조된다. 저장은 상단 context bar 오른쪽과 더보기에 있다.
- 모바일 상단: 앱 바 대신 `‹ 목록 · 작품명 N/M · 저장` context bar. 도구 접기 규칙은 §4.3.
- 본문 끝 카드(댓글보다 먼저): 다음 편/화 제목이 적힌 큰 버튼 → `목록으로`·`작품 목차` → 작게 이전 편. 마지막이면 `작품 목차로 돌아가기`/`회차 목록으로`. 본문 끝 카드로 넘기면 현재 편을 완독 처리하고, 하단 `다음`은 완독 처리하지 않는다.
- 더보기 시트(모든 폭, 데스크톱은 도구줄 `⋯`): 작품 목차 · 저장 · 메모·태그 · 원문 열기 · AA/소설 보기 · 집중 모드 · 링크 복사 · 화면 켜 두기. 가능한 항목만 보인다(§4.4).
- 진행률은 본문 끝 기준이다(긴 댓글이 완독을 막지 않음).
- 상단 context bar에 읽은 %를 표시하고, 더보기의 `읽은 위치` 슬라이더로 긴 본문 안을 이동한다(100%는 다음 화 카드). 가장자리 드래그 스크롤바는 Android 제스처 Back과 겹쳐 쓰지 않았다(구 DSOTM 미니맵의 대체).
- 본문 맨 위 근처(80px)에서는 도구가 항상 보인다.
- 현재 편이 안정되면 다음 편 객체를 한 번 미리 받는다(`requestIdleCallback`, 데이터 절약 모드 제외). 아카이브·텍스트 객체는 immutable 캐시라 다음 이동이 캐시에서 열린다.
- 텍스트 소설 본문 앞의 수집 wrapper(`# 제목` / `#` / 출처 URL) 3줄만 표시에서 빼고, URL은 `원문 열기`로 옮긴다. 다른 `#`·URL은 그대로 둔다. 아카라이브 front-matter의 `url`도 원문 링크가 된다.

## 4.1 본문 아래 목록 (들어온 목록)

본문 끝 카드 바로 아래, 댓글보다 위에 **이 독서 세션이 시작된 목록**을 보여 준다(구 DSOTM `BoardMiniList` 계승).

- 어떤 목록인지는 본문 history entry의 `redstmParent`(들어온 경로)에서 정한다. 그래서 새로고침·앞으로가기·딥링크에서도 같다.
  - `/search?q=…` → 그 검색 결과(검색어·게시판·형식·대상·결합 방식 그대로), `/browse?…` → 그 게시판·형식·정렬
  - `/collections/N` → 작품 목차, `/saved?view=…` → 보관함의 그 탭, 홈 `최근 읽은 글` → 최근 읽음, 홈 최근 게시 글 → 전체 최신 글
  - 딥링크(합성 부모) → 그 글의 게시판
  - 텍스트 → 보던 회차·글 목록 그대로(표시 정렬·검색 필터 포함). 텍스트 목록 정렬은 URL `sort`로 남아 새로고침에도 유지된다
- 넓은 화면에서 옆 목록이 보이는 동안에는 같은 목록이므로 숨긴다. 옆 목록에서 다른 글을 고르는 것도 같은 세션 안의 이동(replace)이다(텍스트 포함).
- 10개씩, 처음에는 **현재 글이 들어 있는 페이지**를 연다. 현재 글은 강조하고 목록에 없으면 그렇게 알린다. `이전/다음`으로 페이지를 넘기고, 행을 누르면 같은 세션 안에서 이동(replace)하므로 Back은 여전히 원래 목록이다. `전체 목록`은 `목록` 버튼과 같다.
- 타입문넷의 연재 소속이 아닌 글은 `이전/다음 글`도 이 목록 순서를 따른다(검색 워커 `page` 메시지가 현재 글의 앞뒤 글을 함께 준다). 연재 편·텍스트 회차는 기존대로 정규 순서다.

## 4.2 텍스트 장서 동등성

- 목록 정렬은 보이는 칩(`오래된순/최신순/이름순`, 작품 목록은 `가나다순/편수 많은순/최신 화순`)으로 바꾸며 URL `sort`에 남는다.
- 작품 행은 `작가 · N화 · 읽음 x/N · 최근 M화`, 회차 목록 상태줄은 `작품 · 작가 · N화 · 읽음 x/N`.
- 검색창 안내는 화면별(회차 찾기 / 작품·작가 / 저장한 자료·메모·태그 / 게시판·분류·글 제목).
- 텍스트 저장에도 메모·태그(더보기 `메모·태그`, 타입문넷과 같은 편집기). 저장함 행에 태그·메모가 보이고 검색된다.
- 홈 `읽던 작품`에 읽는 중인 텍스트 소설이 타입문넷 작품과 함께 최근순으로 나온다.
- 아카라이브 내보내기 형식: `[image] URL` → 이미지, `[video] URL` → 누르면 재생하는 영상(`preload=none`, CSP `media-src 'self' https:` 추가), `[라벨](https://unsafelink.com/실제주소)` → 라벨 링크(래퍼 제거). 아카라이브 이미지 CDN은 서명 URL(`expires`)만 허용하고 내보낸 파일의 서명은 이미 만료(410/403)되므로, 만료된 링크는 불러오지 않는다(서명을 떼거나 `expires`만 지운 주소도 403과 함께 200×200 접근 거부 이미지를 준다 — 2026-09-27 실측).
- 아카라이브 이미지 보관(영상 제외): 뉴토미가 받아 전처리한 이미지가 R2 `media/arca/<CDN 경로 키>`에 있다. Reader는 텍스트 본문의 아카라이브 이미지 경로 키(`20230607sac/<해시>.webp`)를 `POST /api/v1/text/media/resolve`로 확인해 보관본(`/api/v1/text/media/arca/<경로 키>`)으로 바꾸고, 없으면 원본(서명이 살아 있을 때) 또는 `만료된 이미지 링크 · 원문 글에서 보기`를 그대로 둔다. 수집·전송·백필 계약은 [`20_arcalive_media_archive.md`](20_arcalive_media_archive.md).

## 4.3 읽는 동안 도구 접기

- 모든 화면 폭(휴대폰·태블릿·PC)과 TypeMoon·텍스트 장서 공통. 본문을 아래로 48px 읽으면 상단(모바일 context bar, PC·태블릿 읽기 도구줄)과 하단 도구가 함께 접힌다.
- 다시 보이기: 멈춘 채 본문을 짧게 탭(같은 탭으로 다시 접힘), 위로 96px 이상 스크롤(몇 줄 되돌려 읽기로는 나오지 않음), 본문 끝의 다음 글 카드에 닿음, 맨 위 80px 안, 키보드 포커스, PC에서 마우스를 본문 위쪽 64px로 가져감. 마우스 클릭은 텍스트 선택용이라 토글하지 않는다.
- 링크·버튼·이미지·다음 글 카드·본문 아래 목록의 탭, 스크롤 끝의 pointerup, 텍스트 선택, 앱이 위치를 복원하며 생긴 스크롤은 토글/숨김으로 치지 않는다.
- 접힌 동안에도 맨 위 진행 선과 오른쪽 아래 작은 `N%` 표시는 남는다(집중 모드에서는 숨김).
- 기기의 "애니메이션 줄이기"(삼성 "애니메이션 제거" 포함)에서도 똑같이 접히고, 미끄러지는 효과만 없다. 이전에는 이 설정이나 760px 이상 폭에서 도구가 항상 떠 있었다.

## 4.4 읽기 도구 보강 (2026-09-28)

- 읽는 시간: 소설·일반 본문 메타 줄 끝에 `약 N분`(공백 제외 500자/분, 1분 미만은 1분, 60분 이상은 `약 N시간 M분`). AA 본문은 그림이라 표시하지 않는다. 계산은 `reading-model.js`의 순수 함수.
- 더보기 `읽은 위치` 옆에 `남은 시간 약 N분` / `1분 안에 끝` / `끝까지 읽음`(95% 이상)을 보이고, 위치 슬라이더를 움직이면 같이 바뀐다.
- `링크 복사`: 지금 주소(타입문넷 `/read/…`, 텍스트 `/text?…`)를 클립보드에 넣고 `링크를 복사했습니다`를 잠깐 띄운다. 클립보드를 못 쓰면 공유 시트(`navigator.share`)로, 둘 다 없으면 실패를 알린다.
- `화면 켜 두기`: Screen Wake Lock을 쓰는 토글(지원 브라우저에서만 보임, 기본 꺼짐, 저장하지 않음). 본문이 열려 있는 동안만 유지하고, 탭이 가려지면 브라우저가 놓으므로 돌아올 때 다시 요청한다. 본문을 닫으면 해제한다. DSOTM의 자동 wake lock은 계속 쓰지 않는다(`09 §7`).
- 이미지 보기: 화면보다 큰 그림에는 `실제 크기` 단추가 생긴다. 그림이나 단추를 누르면 원래 픽셀 크기로 바꾸고 누른 지점(단추는 가운데)을 화면 가운데에 맞추며, 스크롤로 옮겨 본다. 다시 누르면 `화면에 맞춤`. 작은 그림에는 단추가 없다.
- AA `맞춤`(AA 도구줄 zoom 묶음 맨 앞): 그림의 가장 넓은 줄이 가로 스크롤 없이 들어오는 배율로 줄인다. 100%를 넘겨 키우지 않고, 이미 들어오는 그림은 100%로 돌아간다. 배율은 기존과 같은 전역 `aaZoom`이다.
- 홈 `이어서 읽기` 카드 아래쪽에 읽은 만큼의 red 진행 조각(3px)을 그린다(`DESIGN.md §3`의 red 사용 지도).
- 760px 이상에서 `?`는 읽기 설정을 열고 `키보드 단축키` 목록을 펼친다. 휴대폰 폭에서는 목록을 숨긴다.
- 홈 `자주 보는 게시판`: 게시판 선택 시트의 즐겨찾기 → 최근 본 게시판 순서로 최대 8개 chip. 현재 release에 없는 게시판은 빼고, 누르면 형식·검색 조건을 초기화한 채 그 게시판 전체를 둘러보기로 연다.

## 4.5 발견과 한 손 읽기 (2026-09-28 2차)

- 정렬: 목록 건수 옆 `결과 줄`의 정렬 pill(모든 폭, 필터 시트 밖)에서 바로 바꾼다. 글은 최신순·오래된순에 release가 수를 가질 때 `조회 많은순`·`댓글 많은순`, 작품은 최근 글순·가나다순·편수 많은순에 `조회 많은순`·`댓글 많은순`(보존된 편 합계). 수가 없는 release에서는 그 선택지를 숨기고, 링크의 `sort=views`는 작품 색인이 늦게 도착해도 그때 적용된다. 행에는 `조회 2.5만 · 댓글 3`처럼 줄인 수를 보인다.
- 홈 `오늘의 발견`(읽던 작품·자주 보는 게시판 다음):
  - `오늘의 추천 작품`: 아직 읽지 않은 연재(보존 3편 이상, 단편 묶음 제외) 3개. 날짜로 정해져 하루 동안 같고, 수가 있으면 `1 + log10(1 + 조회 + 5×댓글)` 가중치로 인기 작품이 더 자주 나온다. `다른 추천`은 이 탭에서 다른 3개를 뽑는다.
  - `요즘 화제`: 가장 최근 2,000개 글 중 댓글 많은 순 4개(수가 있을 때만).
  - `이날의 기록 · M월 D일`: 예전 해 같은 날짜에 쓴 글 3개(`N년 전`), 화제에 이미 나온 글은 뺀다.
  - 여기서 연 글의 본문 아래 목록은 그 글의 게시판이다.
- 읽던 작품: 가장 멀리 연 편 뒤에 편이 있고 최신 편이 마지막으로 읽은 뒤에 올라왔으면 `새 편` 표시와 함께 맨 앞에 둔다.
- 작성자: 본문 메타의 작성자 이름을 누르면 그 작성자의 글 검색(`target=author`)을 연다. 휴대폰 키보드는 올리지 않는다.
- 두 손가락: 소설·텍스트 본문을 벌리거나 모으면 글자 크기가 1px 단위로 바뀌고(15–28px) 화면 맨 위 문장을 유지한다. 이 때문에 본문은 브라우저 pinch 확대를 쓰지 않는다(`touch-action: pan-x pan-y`, 이미지는 눌러서 이미지 보기). AA는 기존대로 그림 배율이다.
- `화면 탭으로 넘기기`(설정 → 읽기 동작, 기본 끄기): 켜면 멈춘 탭이 화면 위 25%면 한 화면 위로, 아래 40%면 한 화면 아래로(두 줄 겹침) 넘기고 가운데는 도구를 토글한다. 앞으로 넘길 때 도구를 접고, 넘기는 스크롤은 도구를 다시 부르지 않는다.
- 설치 앱: `앱으로 설치`(브라우저가 설치 가능하다고 알릴 때만 설정에 보임). manifest `shortcuts`로 아이콘 길게 누르기 → 이어서 읽기(`/?continue=1`, 저장 기록을 색인에 맞춘 뒤 이어서 읽기 카드와 같이 열어 Back은 홈)·검색·보관함·텍스트 장서.

## 5. 설정

- 순서: 배경(시스템/밝게/어둡게 segmented, 본문 면 기본/종이) → 글자 크기(`가`/`가` 단계 버튼 + 슬라이더, 15–28px) → 줄 간격 → 좌우 여백(모바일, 12–32px, 기본 20) / 본문 너비(데스크톱) → 서체 → 문단 정렬(왼쪽 맞춤/양쪽 맞춤) → AA → 앱과 기록(운영 현황, 기록 내보내기/가져오기).
- 본문 면 `종이`는 Reader에만 적용하는 따뜻한 면이다(색은 `DESIGN.md §3`). 문단 정렬은 소설·일반·텍스트 본문에만 적용하고 AA는 원본 정렬을 유지한다. 정렬을 바꿀 때도 화면 맨 위 문장을 유지한다.
- 세 값은 user-state v2 `settings.readerSurface`(`default|paper`)·`settings.proseAlign`(`start|justify`)·`settings.tapPaging`(`off|on`)이다. 없는 기존 파일은 기본값으로 보정되고 가져오기 미리보기의 `기본값 보정`에 이름이 나온다(스키마 버전 변화 없음).
- 글자 크기·줄 간격·여백·서체를 바꿔도 **화면 맨 위 문장이 그대로** 남는다(`public/text-anchor.js`, 레이아웃 기하 기반이라 시트가 열려 있어도 동작). 텍스트 본문의 읽기 위치도 같은 문자 anchor로 저장한다.
- 사용자 상태 스키마는 그대로(v2 / text v1). `proseSize` 상한 24→28, `proseMargin` 추가는 범위를 넓히는 변경이라 기존 파일이 그대로 유효하다.

## 6. 게시판 선택과 필터

- 게시판은 일반 필터에서 분리된 **게시판 바**(모바일: 목록 아래·하단 탭 위, 넓은 화면: 탭 아래)에서 고른다. 시트에는 검색, 즐겨찾기(★, 행 선택과 별도 버튼), 최근 본 게시판 4개, release `group_name` 기준 접이식 그룹이 있다. 그룹 제목은 펼치기/접기만 한다.
- 고르면 즉시 그 게시판만 보인다. 선택한 게시판을 숨기는 형식(AA/소설) 조건은 풀고 상태줄에 알린다. `×`로 전체 게시판.
- 즐겨찾기·최근·펼침은 `redstm.boardNav.v1`(이 브라우저, 상태 내보내기에 포함되지 않음).
- 모바일 필터 시트는 **임시값 + 적용**: 적용 전에는 목록이 바뀌지 않고 X·Esc·Back은 취소한다. `전체 초기화` 중복 버튼은 없앴다. 읽기 설정은 즉시 반영이다. 정렬은 2026-09-28부터 시트 밖 결과 줄에 있고 즉시 반영된다(§4.5).

## 7. 바뀐 기존 계약

| 기존 | 새 계약 |
|---|---|
| 다음/이전 편마다 history가 쌓이고 Back이 이전 편으로 감 | 회차 이동은 replace, Back은 목록 |
| 직접 링크 Back은 앱 밖 | 합성 부모 목록으로 1회 |
| 텍스트 전용 뷰어(`#text-reader…`) | 공통 Reader |
| 하단 `목록/이전/저장/다음/설정` | `목록/이전/다음/설정/더보기` |
| 읽기 설정 첫 항목 운영 현황, `현재 글` 묶음 | 운영은 설정 맨 아래, 글 동작은 더보기 |
| 테마 select | segmented control (`[data-theme-choice]`) |
| 게시판 select가 필터 안 | 게시판 바 + 시트 (`#board-filter`는 값만 보관) |
| 모바일 읽기 중 앱 바 | Reader context bar |
| 뒤로 와서 검색창 자동 focus | 명시적으로 검색 탭을 누를 때만 focus |

# Reader 탐색 구조 개선

- 상태: Phase 1 배포 완료; Phase 2 실사용 판정 대기
- 기준일: 2026-09-19
- 대상: `edge/public/index.html`, `app.js`, `app.css`, Reader E2E
- 원칙: 새 API·프레임워크 없이 현재 검색 색인과 작품 색인을 재사용한다.

## 문제

현재 `탐색` 한 화면이 최신 목록, 게시판 선택, 작품 목록, 키워드 검색과 검색 옵션을 모두
담는다. 모바일에서는 검색하지 않고 한 게시판의 글을 훑을 때도 검색 폼이 화면 상단의 절반을
차지한다. 홈은 최근 글 몇 건을 보여 주지만 주요 소설 접근 경로 역할은 하지 못한다.

## 정보 구조 결정

| 목적 | 주 메뉴 | URL | 화면 |
|---|---|---|---|
| 게시판·작품을 훑기 | 둘러보기 | `/browse` | 게시판 글/작품 탭, 게시판·형식·정렬만 표시 |
| 제목·작성자 등으로 찾기 | 검색 | `/search` | 글/작품 탭, 검색어와 상세 검색 옵션 표시 |
| 저장·최근 읽기 | 보관함 | `/saved` | 기존 로컬 상태 유지 |
| 읽기 환경 변경 | 설정 | `/settings` | 기존 dialog 유지 |
| 개인 요약 | ReDSTM 로고 | `/` | 이어 읽기·최근 기록; 주 메뉴에서는 제외 |

- 작품 상세 URL `/collections/:id`는 유지한다.
- 기존 `/collections` 링크는 작품 둘러보기로 유지한다.
- 작품 검색은 `/search?scope=collections`로 분리한다.
- 홈은 삭제하지 않는다. 이어 읽기와 최근 기록의 효용은 있지만 반복 탐색의 주 경로는 아니다.
- 모바일 하단 메뉴는 네 칸을 유지한다. 메뉴를 늘리거나 별도 게시판 API를 만들지 않는다.

## 단계와 인수 조건

### Phase 1 — 목적 분리

- [x] 주 메뉴를 `둘러보기 / 검색 / 보관함 / 설정`으로 변경한다.
- [x] `/browse`와 `/search`가 같은 색인을 쓰되 서로 다른 제어 UI를 보인다.
- [x] 둘러보기에서는 검색어·검색 필드·단어 결합 제어를 숨긴다.
- [x] 글/작품 scope와 URL, 뒤로 가기, 목록 위치를 보존한다.
- [x] 모바일에서 게시판 글 목록 앞 제어 영역이 검색 화면보다 확실히 짧다.

### Phase 2 — 게시판 선택 경험

- [ ] 실제 게시판 수와 그룹명을 확인해 native select가 충분한지 실기기에서 판정한다.
- [ ] select가 느리거나 찾기 어렵다는 증거가 있을 때만 그룹형 게시판 선택 화면을 추가한다.
- [ ] 선택한 게시판 이름과 전체/현재 결과 수를 목록 문맥에 명확히 표시한다.

### Phase 3 — 홈 정리

- [ ] 실제 사용 후 이어 읽기·최근 읽기만 남길지, 홈을 `/browse`로 연결할지 결정한다.
- [ ] 최신 글이 오래돼 홈 효용을 떨어뜨리는 경우 최신 글 영역을 둘러보기 바로가기로 대체한다.

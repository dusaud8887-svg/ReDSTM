## 2. 한글 처리 점검 결과(문제 없음)

- `<html lang="ko">`(앱·/ops), 제목·작품명·목록 행은 `word-break: keep-all` + 넘칠 때 `overflow-wrap`.
- 정렬: `Intl.Collator("ko-KR", { numeric: true })`, `localeCompare(…, "ko-KR", { numeric: true })` — `2화 < 10화`.
- IME: 검색 Enter·찾기 Enter·스마트 서재·텍스트 장서 Enter가 `isComposing`/`keyCode 229`에서 멈춤. 제목 제안은
  조합 중에도 따라가고 전체 글 검색은 `compositionend` 뒤에 실행(`app.js` 검색 입력).
- 조사: 변수 뒤 고정 조사 3곳 모두 맞음(`위치로`, `저장한 글이`·`최근 읽음이`, `N편은/으로`).
- 공백 무시 검색(`b9e5a4c`)과 초성 검색(`es-hangul`)은 기존 테스트가 다룬다.

## 3. 제안(설계 결정 필요 — 구현하지 않음)

1. **소설 작품 화면의 찾기 입력 두 개**: `몇 화?`+`찾기`와 그 아래 `회차 찾기 (예: 120화, 외전)`가 같은 화면에 있다.
   회차 찾기가 `120화`도 받으므로 소설 작품에서는 `몇 화?`를 빼고 회차 찾기에서 Enter = 첫 결과로 이동을 제안.
   (타입문넷 작품은 회차 찾기가 없어 `몇 편?` 유지.)
2. **검색의 `필터` 단독 줄**: 칩이 없는 검색 화면에서 `필터` 버튼 하나가 한 줄(약 40px)을 차지한다.
   결과 줄(`30건 · 최신순`) 오른쪽에 합치면 첫 화면에 행 1개가 더 보인다.
3. **기록 기본 탭**: 탭 순서는 `읽는 중 · 저장 · …`인데 하단 `기록`은 두 번째 `저장`을 연다. 저장이 비어 있고
   읽는 중이 있으면 빈 화면(`저장한 글이 없습니다`)부터 보인다. 첫 탭을 기본으로 하거나 빈 상태에 `읽는 중 보기`
   링크를 두는 안. 기존 습관을 바꾸므로 사용자 결정.
4. **본문 `keep-all` 선택지**: 소설 본문은 음절 단위 줄바꿈(종이책 관례)이다. 웹소설 앱 일부는 어절 단위를 쓴다.
   `모든 설정`에 `낱말 단위 줄바꿈`(기본 끔)을 두는 안 — 정렬 `양쪽 맞춤`과 함께 쓰면 공백이 벌어질 수 있어 둘의 조합 확인 필요.
5. **빈 상태 문구 → 다음 행동**: `저장한 글이 없습니다`처럼 끝나는 빈 상태에 방법 안내
   (`글을 읽다가 위쪽 책갈피를 누르면 여기에 모여요`)를 붙이는 안(Nielsen #10, docs/26 §4.4).
